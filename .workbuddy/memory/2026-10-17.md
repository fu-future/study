### 关键设计决策（后续不要轻易改）
1. **enum-free schema**：不用 Prisma 原生 enum / Json / 数组 / `@db.*`，
   枚举用 String + `src/lib/domain/enums.ts` 的 zod 校验，小结构存 TEXT JSON
   （`src/lib/db/json.ts`）。目的：同一份 schema 在 SQLite 与 PostgreSQL 上都成立。
2. **不用 rehype-sanitize**：它在 KaTeX 前运行会剥掉公式节点。安全靠
   react-markdown 默认不渲染原生 HTML + `urlTransform` 白名单协议。
3. **掌握度算法与 AI 完全解耦**（`src/lib/diagnosis/engine.ts`，纯函数）：
   加权证据（独立完成度 × 记忆衰减 × 难度校正），证据不足返回"还需要更多练习"
   而不是假分数。AI 只负责把结论翻译成人话（可失败，失败不影响诊断）。
4. **方言差异收敛在 `src/lib/db/search.ts`**：SQLite 的 LIKE 不区分大小写，
   PostgreSQL 需要 `mode:'insensitive'`，由 `containsFilter()` 按运行时方言自动切换。
5. Mock Provider **绝不编造解题内容**，只返回结构正确的占位 + 明确提示。

### E2E 环境踩坑（重要，下次直接用现成方案）
1. **Playwright 把配置编译成 CJS** → `e2e/env.ts` 里**不能用 `import.meta.url`**，
   改用 `process.cwd()`（要求从项目根执行）。
2. **Playwright 与 Next 都会清理自己的输出目录**（`test-results`、`playwright-report`、
   `.next-e2e`），沙箱删除守卫会拦住 → 统一在 **`pretest:e2e`** 钩子
   （`scripts/reset-e2e-distdir.mjs`）里**改名保留**而不是删除。
   注意必须在 **webServer 启动之前**做：globalSetup 太晚，文件已被占用会 EPERM。
3. `next build` 在本机有两个环境级障碍：
   - `.next/trace` 的 **EPERM**：只发生在 `.next` 被 `mv`/`mkdir` 重建过之后；
     **Next 自己创建的 `.next` 就正常**。结论：**不要移动 `.next`，原地构建**。
   - 收尾清理 ≥50 个文件触发删除守卫 → 构建命令临时设
     `CODEBUDDY_SAFE_DELETE_ENABLED=0`（删除范围仅 `.next`，已 gitignore）。
