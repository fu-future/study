# 异地使用：让手机在任何地方都能打开

> 场景：这台 Windows 电脑放在某处（家里/宿舍/办公室）一直开着，
> 你在**另一个地方**用手机浏览器打开它，正常登录、拍题、问 AI。
>
> 本文不谈"同一 Wi-Fi"（那是 [docs/LAN_DEPLOY.md](LAN_DEPLOY.md) 的内容），
> 只讲跨网络怎么打通。

---

## 0. 一句话结论

| 你的条件 | 推荐方案 |
|---|---|
| 不想折腾、不想买域名 | **Tailscale**（免费，加密，不用改路由器）← 首选 |
| 这台宽带已有公网 IPv6（**你这台就有**） | IPv6 直连 + 路由器放行（不用装软件，但前缀会变） |
| 已有域名 | Cloudflare Tunnel（TLS + 访问控制） |

本机实测情况（2026-10-18）：

```
✅ 服务双栈监听（IPv4 + IPv6 同时可用）
✅ 本机通过公网 IPv6 地址访问 /api/health → HTTP 200
✅ 存在公网 IPv6：2409:8a15:3816:4da0:...（中国移动）
ℹ️ Tailscale 未安装
❌ 从真正的外部网络连入：本机无法自测（需要异地的网络与你的路由器权限）
```

---

## 1. 为什么不能"直接把 3100 端口映射到公网"

三个原因，都不是"太保守"，而是确实会出事：

1. **大概率根本不通**。国内家宽绝大多数没有公网 IPv4（在运营商大内网里），
   路由器上做端口映射也没用 —— 数据到不了你家。
2. **明文传输**。HTTP 下同链路上的人可以看到题干、答案、聊天内容，
   登录 Cookie 也是明文（虽然 httpOnly，但不加密）。
3. **没有任何访问控制**。这个应用是"单机自用"定位：会话是签名 Cookie、
   限流在进程内、没有多因素认证。一旦公网可达，等于对所有扫描器开放。

所以下面三种方案，共同点都是：**要么加一层加密隧道，要么至少把暴露面缩到最小**。

---

## 2. 方案对比

| 方案 | 需要什么 | 加密 | 国内可用性 | 主要代价 |
|---|---|---|---|---|
| **Tailscale** | 电脑与手机各装一个客户端，同一账号 | ✅ WireGuard 端到端 | 基本可用；偶尔走中继，速度一般 | 两端都要装、都要登录 |
| **IPv6 直连** | 宽带有公网 IPv6 + 路由器放行 | ❌ 默认没有（可自行加 TLS） | 取决于运营商与手机网络 | 前缀会变；明文；公网暴露 |
| **Cloudflare Tunnel** | 一个域名（可免费二级域名） | ✅ HTTPS | 可用，但国内速度一般 | 需要域名与 Cloudflare 账号 |
| **frp 自建** | 一台有公网 IP 的服务器 | 取决于配置 | 可用 | 要买服务器，要自己维护 |
| **花生壳 / 蒲公英** | 商业账号 | 部分支持 | 好 | 免费额度有限，按带宽收费 |

下面详细讲前两个；后三个只给关键差异，不展开（它们的配置各家不同，写死步骤反而容易误导）。

---

## 3. 方案 A：Tailscale（推荐）

### 3.1 它解决什么问题

Tailscale 把「电脑」和「手机」组成一个虚拟局域网：
两台设备都登录同一个账号后，手机会拿到一个 `100.x.x.x` 的地址，
访问 `http://100.x.x.x:3100` 就等于访问这台电脑。

关键点：

- **不需要公网 IP、不需要改路由器、不需要端口映射**（走的是设备主动发起的连接）
- **全程 WireGuard 加密**，所以即使服务本身是 HTTP，链路也是加密的
- 免费个人版够用（最多 100 台设备）

### 3.2 三步打通

**第 1 步：电脑端**

1. 打开 <https://tailscale.com/download/windows> 下载并安装
2. 安装后登录（推荐用 Google/GitHub/邮箱，记住用哪个）
3. 装完任务栏会出现 Tailscale 图标，状态应为 **Connected**

装好后拿本机地址：

```bash
tailscale ip -4
# 输出形如 100.101.102.103
```

**第 2 步：手机端**

1. App Store / 应用商店搜索 **Tailscale** 安装
2. 用**同一个账号**登录
3. 打开开关（iOS 会提示添加 VPN 配置，允许即可）

**第 3 步：验证**

在手机上打开浏览器，访问：

```
http://100.101.102.103:3100     # 换成你 tailscale ip -4 输出的那个地址
```

能打开登录页就成功了。

> 也可以给设备起个好记的名字（Tailscale 后台 → Machines → 改名），
> 开启 MagicDNS 后就能用 `http://我的电脑:3100` 这样的名字访问。

### 3.3 让本机自动显示"异地访问"地址

项目里的启动脚本会自动识别 `100.64.0.0/10` 网段：

```bash
npm run lan
```

```
  同一 Wi-Fi   http://192.168.1.6:3100   (WLAN)
  异地访问     http://100.101.102.103:3100   (Tailscale · 已通过 Tailscale 组网)
```

看到「异地访问」这一行，说明隧道已经就绪。

### 3.4 可选：让它走 HTTPS

Tailscale 可以为你的设备签发一个 `*.ts.net` 域名证书，浏览器地址栏会显示小锁，
也可以正常使用 `COOKIE_SECURE=true`：

```bash
tailscale serve --bg 3100
# 之后用 https://<设备名>.<你的tailnet>.ts.net 访问
```

注意两点：
- 这需要在 Tailscale 后台开启 HTTPS Certificates（免费）
- 开启后把 `.env` 里的 `APP_URL` 改成那个 https 地址，`COOKIE_SECURE` 设为 `true`，
  然后重启服务（否则 Cookie 的 Secure 标记与实际协议不一致，登录会存不住）

### 3.5 常见问题

| 现象 | 处理 |
|---|---|
| 手机装了但还是连不上 | 手机端 Tailscale 开关是否打开（iOS 顶部会有 VPN 标识）；两端是否同一账号 |
| 显示 Connected 但很慢 | 可能走了中继（DERP）。`tailscale ping <手机名>` 看是否 direct；同一运营商网络通常能直连 |
| 电脑重启后连不上 | Tailscale 默认开机自启；若被安全软件拦了，检查服务 `Tailscale` 是否在运行 |
| 想彻底断开 | 电脑端 `tailscale down`，手机端关开关 |

## 4. 方案 B：IPv6 直连（你这台已经具备条件）

### 4.1 本机实测

```
公网 IPv6 地址：2409:8a15:3816:4da0:331f:f60e:5b88:83ae（中国移动）
监听：::（双栈），netstat 同时出现 0.0.0.0:3100 与 [::]:3100
本机通过公网 IPv6 访问 /api/health → HTTP 200
```

也就是说，**服务这一侧已经通了**。剩下的是路由器和外部网络两件事。

> 为什么脚本要绑 `::` 而不是 `0.0.0.0`：`0.0.0.0` 只监听 IPv4，
> IPv6 客户端会直接连不上。这个坑我在改脚本时实测踩过。

### 4.2 还差两步

**第 1 步：路由器放行**

不同路由器位置不同，大致在：
`路由器后台 → 防火墙 / 安全 → IPv6 防火墙`（或「IPv6 入站规则」）
→ 允许来自外网的入站 TCP 3100，目标指向这台电脑的 IPv6 地址。

有的路由器直接叫「IPv6 防火墙开关」，关掉它等于全部放行 —— 不建议。
能按端口放行就按端口。

**第 2 步：手机侧具备 IPv6**

手机用 4G/5G 时一般都有 IPv6；连某些 Wi-Fi 时可能没有。
测试方法：手机浏览器打开 <https://test-ipv6.com>，看是否拿到 IPv6 地址。

然后访问：

```
http://[2409:8a15:3816:4da0:331f:f60e:5b88:83ae]:3100
```

⚠️ IPv6 地址必须用方括号包起来，否则浏览器会把冒号当成端口分隔符。

### 4.3 前缀会变，怎么长期用

家宽的 IPv6 前缀（`2409:8a15:3816:4da0::/64`）在**重新拨号/路由器重启后可能变化**，
后半段（接口标识）通常不变，但前缀一变整条地址就失效。

两个应对办法：

1. **路由器自带 DDNS**（很多国产路由器支持 IPv6 DDNS）—— 开启后用一个固定域名访问
2. **自建 ddns-go**（开源，支持阿里云/腾讯云/DNSPod/Cloudflare）：
   定时把当前 IPv6 写到 DNS 记录，用域名访问

### 4.4 风险提示（比 Tailscale 高，请注意）

- **明文**：链路上任何人都能看到内容。要真正安全，需要自己上 HTTPS（反向代理 + 证书）
- **直接暴露**：整个互联网都能扫到这个端口。必须是强密码 + 关闭自助注册
- **运营商可能封端口**：常见封 80/443/8080；3100 一般不受影响，但不保证

如果这三条你不想折腾，回到方案 A。

## 5. 方案 C：Cloudflare Tunnel（有域名时）

适合已经买了域名的人：`cloudflared` 在电脑上建一条出站隧道，
Cloudflare 那边给一个 HTTPS 域名，再配 Access（邮箱白名单）就能做到「只有你能进」。

关键命令（仅示意，具体以 Cloudflare 文档为准）：

```bash
cloudflared tunnel login
cloudflared tunnel create study-coach
cloudflared tunnel route dns study-coach study.你的域名.com
cloudflared tunnel run --url http://localhost:3100 study-coach
```

优点：HTTPS、无需开放入站端口、可加身份验证。
缺点：国内访问 Cloudflare 免费线路速度不稳定；需要域名。

## 6. 异地场景下必须做的安全动作

比局域网更严格，因为**攻击面从"同 Wi-Fi 的人"变成"整个互联网"**：

| 必做 | 说明 |
|---|---|
| 删掉演示账号 / 改密码 | `demo@study.local` 的密码是公开的，异地暴露前必须处理 |
| `ALLOW_SELF_SIGNUP=false` | 否则任何知道你地址的人都能注册进来 |
| 换掉 `SESSION_SECRET` | 泄露即可伪造任意用户会话 |
| 强密码 + 不要复用 | 这是唯一的身份凭据 |
| 优先加密通道 | Tailscale / Cloudflare；IPv6 直连请自行加 TLS |
| 定期备份 | `npm run backup`；被入侵时至少数据还在 |
| 不要长期无人值守暴露 | 不用的时段停掉服务，或关掉隧道 |

## 7. 协议与配置的对应关系（配错会"登录不上"）

| 你实际使用的地址 | `APP_URL` | `COOKIE_SECURE` |
|---|---|---|
| `http://192.168.x.x:3100`（局域网） | 可以保持 `http://localhost:3000` | `auto` 或 `false` |
| `http://100.x.x.x:3100`（Tailscale） | 同上 | `auto` 或 `false` |
| `https://xxx.ts.net`（Tailscale Serve） | 改成这个 https 地址 | `true`（或 `auto`） |
| `https://study.你的域名.com`（Cloudflare） | 改成这个地址 | `true`（或 `auto`） |

原理：带 `Secure` 的 Cookie 只在 HTTPS 下回传。**用 http 访问却设了 `true`，
表现就是"登录返回 200，但刷新又回登录页"，而且没有任何报错。**

## 8. 连不上时怎么查

```bash
npm run net:check
```

它会依次检查：服务是否在监听 → 局域网地址是否可达 → 有没有 Tailscale 通道 →
有没有公网 IPv6，并直接告诉你卡在哪一层。

常见结论对照：

| 输出 | 含义 |
|---|---|
| `127.0.0.1:3100 可连接` + 局域网 ❌ | 防火墙没放行 → 见 LAN_DEPLOY 第 1 节 |
| 局域网 ✅ / 异地通道 ℹ️ 未安装 | 还没做异地方案，选 A 或 B |
| Tailscale 已就绪但手机连不上 | 手机端开关没开，或不在同一账号 |
| 有公网 IPv6 但外部连不进来 | 路由器没放行，或手机侧没有 IPv6 |
